# 设计文档 · 麦门开饭 McRogue

## 1. 一句话

把「今天吃什么」从**一次性的计算题**，变成**一局有三回合、有取舍、能晒结果**的游戏；
所有数值来自麦当劳 MCP 的真实数据。

---

## 2. 为什么是"游戏"而不是又一个点餐助手

（本节为项目立论，写给自己与评审看。）

市面上已有大量「输入预算 → 查菜单 → 领券 → 核价 → 下单」的线性工具。
它们解决"这一单怎么最省"，但有两个天然短板：

1. **与用户的真实动机错位**：人们点麦当劳时的真实纠结不是"求最优解"，而是"我今天想吃点什么、值不值"；
2. **不可传播**：一次点餐的结果没有分享价值，工具用一次就沉淀不下来。

McRogue 把痛点重新表述为**一日三餐的资源分配问题**：
预算有限、热量额度有限、券会过期、活动每天不同——这本身就是天然的**肉鸽约束**。

> **把"算一单"变成"打一天"**：结果是一张可以晒的战报，而不是一串价格。

## 3. 核心循环

```
开局定盘
  ├─ now-time-info            判定时段
  ├─ query-nearby-stores      选门店
  ├─ campaign-calendar        抽「今日事件」
  ├─ auto-bind-coupons        领券（道具入库）
  └─ 四路券池汇总              标出「临期券」
        │
        ▼
   ┌──────────── 三回合（早 / 正 / 晚）────────────┐
   │  query-meals  → 出「手牌」                     │
   │  query-meal-detail + list-nutrition-foods 补全 │
   │  玩家选 1~2 件                                 │
   │  calculate-price 真实核价（含券）              │
   │  score.py 结算：省钱率 / 热量达成 / 券利用     │
   └───────────────────────────────────────────────┘
        │
        ▼
     战报（总分 + 段位 + 锐评 + 可分享图）
        │
        └─ 用户显式确认后 → create-order（可选）
```

### 回合之间的张力（肉鸽感来源）

| 机制 | 作用 |
|---|---|
| 午餐超热量 | 晚餐额度被压缩，逼出取舍 |
| 用掉临期券 | 后续回合券池变小，"现在用还是留着"成为决策 |
| 今日事件 | 当月真实活动改变约束（加价购、联名限定、限时优惠） |
| 取餐方式 | 到店自取省配送费 vs 麦乐送省时间，影响预算分配 |

## 4. 双形态：为什么必须有一个"不用 Token 也能玩"的版本

| 形态 | 文件 | 面向谁 | 作用 |
|---|---|---|---|
| **Skill 本体** | `SKILL.md` + `scripts/` | 装了 WorkBuddy + MCP Token 的人 | 真实数据、真实核价、可真实下单 |
| **可玩网页版** | `web/index.html`（单文件） | 所有人 | 零门槛体验、可分享、可嵌入 |

**两者共用同一套结算逻辑**（`scripts/score.py` 的规则在网页版中以等价 JS 实现），
保证"网页版玩到的规则"和"Skill 里跑到的规则"一致。

设计上刻意让网页版**内置真实菜单快照**（`data/snapshot.json`），
使离线状态下的体验仍然是"真的麦当劳菜单"，而不是编造的数字。

---

## 5. 战报（传播单元）

结算后产出一张竖版战报，包含：

- 三回合实际花费与省钱率
- 全天摄入热量 vs 额度
- 用掉的券
- 段位与一句话锐评
- 项目二维码/链接

网页版用 Canvas 直接导出 PNG，**长按保存即可发朋友圈**。

> 战报是本项目的"传播单元"：游戏可以只玩一次，但战报会被晒出去。

## 7. 目标用户

| 人群 | 为什么用 |
|---|---|
| 每天纠结吃什么的上班族 | 60 秒替自己做决定，还顺手把券用掉 |
| 控卡/健身人群 | 用真实营养数据做完一天的热量分配 |
| 学生 / 预算敏感人群 | 用真实券和核价把一天预算花满 |
| 开发者 | 一个"用真实 API 当游戏数据源"的接口调用范例 |

## 9. 边界与合规

- 不下单（默认）；下单必须显式确认；
- 不做医疗/营养建议，只呈现官方数值；
- 不与其他品牌作比较（活动规则明确禁止）；
- 不硬编码 Token，不落盘个人信息；
- 不使用任何自动化手段影响排名。
